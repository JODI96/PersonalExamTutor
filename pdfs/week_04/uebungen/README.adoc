== Einführung

In dieser Übung wird PostGIS vorgestellt,
inkl. der entsprechenden Datenstrukturen und der damit verbundenen SQL-Abfragen.
Der grundlegende Ablauf bei der Daten-Verwaltung und -Analyse ist immer ähnlich
(EVAP-Prinzip):

1. leere Datenbank erzeugen und Schema erstellen
2. Daten laden
3. Daten analysieren
4. präsentieren

Bei Geodaten-Typen sind dabei jedoch einige Schritte besonders:

* Bei Schritt 1 Eingabe (DB und Tabellen erstellen)
muss bei der DB die Erweiterung PostGIS geladen werden.
Beim Geometrie-Attribut sind nebst Spalten-Typ `GEOMETRY`
weitere Angaben („Modifier“) nötig.

* Bei Schritt 2 Eingabe und Verwaltung (Daten laden)
kommen „Bulk“-Datenlade-Programme zum Einsatz,
 weil Geodatensätze typischerweise gross sind.

* Schritt 3 (Analysieren)
besteht aus SQL-Anfragen.

* Schritt 4 (Präsentieren) schliesslich
verlangt nach speziellen Programmen zur Präsentation
(Visualisierung, Kartendarstellung, GIS),
da den Koordinatenzahlen alleine wenig anzusehen ist.

.Tipps

* PostGIS Manual: https://postgis.net/documentation/ → Stable Branch User Documentation

* PostGIS https://www.postgis.us/downloads/postgis21_cheatsheet.pdf[Cheatsheet (PDF)]

* Der Name des Attributs vom Typ Geometrie ist oft `geom`.
Manchmal ist auch `geometry` oder `the_geom` gebräuchlich.

.Zur Info
NOTE: Wir verwenden hier Vektor-Geodaten im modernen GeoPackage-Format.
Weit verbreitet sind bzw. waren bisher sog. Shapefiles.
Das mit PostGIS mitgelieferte Command-Line-Konverter `shp2pgsql`
konvertiert Shapefiles in SQL-Dateien (mit ``INSERT``s).
Diese SQL-Dateien können dann mit `psql` in die PostgreSQL/PostGIS-Datenbank geladen werden.
Das eignet gut sich für grossen Datenmengen.
Ein bessere Command-Line-Konverter ist `ogr2ogr` von GDAL.org; vgl. unten

== Aufgabe 2: PostGIS-Datenbank `gisdb` erstellen

IMPORTANT: In diesem Abschnitt
sind nur die *fett* gedruckten Befehle einzugeben.
Der Rest sind Ausgaben des Computers.

. Eine leere PostGIS-Datenbank `gisdb` erstellen
Variante SQL::
+
[subs=+quotes]
----
postgres=# *create database gisdb;*
CREATE DATABASE
----

Variante GUI im pgAdmin::
Rechts-Klick und „Create Database“; +
dann die Extension „postgis“ mit „New Object > New Extension…“ installieren.

Variante Command Shell (gegeben die Executables sind im Systempfad)::
Starten Sie eine Konsole (DOS/Linux Shell):
+
[subs=+quotes]
----
shell> *createdb -U postgres gisdb*
----

. Nachdem die DB erstellt wurde, aktivieren Sie dort die PostGIS-Extension:

Variante SQL::
+
.Zur Datenbank `gisdb` verbinden (`psql`)
[subs=+quotes]
----
postgres=# *\c gisdb*
You are now connected to database "gisdb" as user "postgres".
gisdb=#
----
(In pgAdmin stattdessen per Kontext-Menü ein SQL-Eingabefenster für die DB `gisdb` öffnen.)
+
.PostGIS für `gisdb` aktivieren (in `psql` oder pgAdmin)
[subs=+quotes]
----
gisdb=# *CREATE EXTENSION postgis;*
CREATE EXTENSION
----

Variante Command Shell::
+
[subs=+quotes]
----
shell> *psql -U postgres -d gisdb --command="CREATE EXTENSION postgis;"*
CREATE EXTENSION
----

. Die leere Datenbank `gisdb` sollte nun bereit sein.
Das kann folgendermassen überprüft werden (sollte eine Row liefern):
+
[subs=+quotes]
----
shell> *psql --username postgres --dbname gisdb --command="SELECT postgis_full_version();"*
----
+
oder (etwas kürzer):
+
[subs=+quotes]
----
shell> *psql -U postgres -d gisdb -c"SELECT postgis_full_version();"*
----
+
oder: `psql` starten (z.B. als User `postgres`) und die Query dort eingeben:
+
[subs=+quotes]
----
gisdb=# *SELECT postgis_full_version();*
----

== Aufgabe 4: Räumliche Query lesen

Schauen Sie diese Query an:

[source,sql]
----
WITH mylocation AS ( -- Nelson Pub Rapperswil
  SELECT st_transform(st_geomfromtext('POINT(8.81642 47.22541)', 4326), 21781) AS geom
)
SELECT
  "name",
  st_astext(orte.geom,0) AS geom,
  st_distance(orte.geom,mylocation.geom)::int AS distance_in_m
FROM orte
JOIN mylocation ON st_dwithin(orte.geom, mylocation.geom, 10000)
ORDER BY distance_in_m;
----

Was machen die verschiedenen «`ST_`»-Funktionen?
Sehen Sie in der PostGIS-Dokumentation nach.

* `ST_GeomFromText`
* `ST_Transform`
* `ST_AsText`
* `ST_Distance`
* `ST_DWithin`

Was für eine Frage ermittelt obige Query?
Welches Ergebnis erwarten Sie?
Dokumentieren Sie ihre Annahme, bevor Sie die Query ausprobieren.

Sehen Sie sich zusätzlich diese Funktion an:

* `ST_Buffer`

== Aufgabe 6: Flächenverschnitt (Spatial Analysis)

Erfassen sie eine Flugschneise mit https://geojson.io ,
schreiben dann eine Query in SQL mit
[source,sql]
----
select st_intersection(g1,g2) from gemeinden g1 (g2…)
----
und visualisieren Sie schliesslich das Resultat mit QGIS Desktop
und wieder mit geojson.io im Webbrowser:
